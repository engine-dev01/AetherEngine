--- 5. closure names: blutter's asm joined to the raw string table ---
  blutter names each Dart closure `<name>@<libraryId>` in the snapshot's string table, so a
  closure found in asm/ can be located as raw bytes - and the library id says which library
  it really belongs to:
    _pfc   asm Ieg.dart:379 (class _dX)  <->  raw '_pfc@286240726' at file 0x269c4
    _cec   asm Ieg.dart:468 (class _hX)  <->  raw '_cec@122399801' at file 0x2ba08
    _eec   asm Ieg.dart:471 (class _hX)  <->  raw '_eec@122399801' at file 0x3cdb5
  library ids involved: 122399801, 286240726 -> the 3 handlers are spread over 2 Dart libraries
  CASE-SENSITIVITY TRAP (checked, and NOT linked): the pool-absent string 'encryptedData'
  sits next to `_Pfc@227452173` in the string table. Dart names are case-sensitive and
  asm/Ieg.dart contains BOTH `_pfc(dynamic, MethodCall)` (line 379) and `_Pfc(dynamic, Ca)`
  (line 440), with different library ids (286240726 vs 227452173). `encryptedData` therefore
  belongs to the `_Pfc`/`Ca` closure, NOT to the MethodCall handler `_pfc`.
